This does not retry provider capture, create a link, use a stale count as current, or replace the server's tenant and operator checks. The release check must observe a fresh page load and the error state if the backend remains unavailable.

For attention jobs whose canonical customer/site identity is still held, a separate **user-opened** section groups saved job rows only by exact Commusoft customer ID inside the same connection. It reads the existing authenticated, audited paged job RPC at a fixed snapshot and stops at the first Open job; no provider call, database migration or identity write is added. The 200-row cap is labelled as a bounded first portion if reached. Missing parent IDs or inconsistent names remain individual jobs; jobs confirmed for that same saved source version are excluded when that read is available, while a changed version may need rechecking. The section explicitly says these are recorded source names, not verified ServiceOS links. This is a way to find the remaining work without relaxing the approved matching rule.
