## Minimal source-only wiring prepared

`learn-count-view.ts` projects the existing `learn-status/1` result into the existing metric cards. `LearnReview` accepts an optional result and an explicit selected tenant; it does not fetch, authorise, load credentials or query tables. The validator and expiry logic are a pure excerpt of f19cb393 `src/lib/learn-status.ts`, with transport/auth imports excluded. Fresh zero stays zero; partial stays qualified; foreign tenant, unknown schema, invalid totals, future/expired snapshots, denial, loading and error clear counts. Storage timestamps retain their storage meaning; they are never shown as last successful sync. Slack, Team and all connector/sync badges remain Unknown/Unverified.

Both shell callers currently supply only the synthetic selected tenant and **no observation**. Thus hosted/backend binding is intentionally absent, default values remain Unknown, and the existing labelled opt-in examples remain local fixtures. No production payload is copied to TEST.

## Smallest prerequisites for hosted binding

1. Conductor/Core agree an existing client-safe read permission and selected-tenant/operator policy. Preserve View-As restrictions; no platform grant borrowed for ordinary clients. Independent Assurance accepts the exact backend candidate and confirms its deployed version before enabling the read.
2. Existing backend contract owner adds a metadata-only status observation to its existing projection, with tenant, observation/expiry, separate read errors and actor checks. Reuse existing email health, connector/account watermarks and phone reconciliation rather than new ingestion. Include explicit mailbox selection/pause/deferral reason, inventory observation/freshness, per-enabled-mailbox successful message sync and incomplete coverage. Never infer a deferral reason from disabled alone.
3. Slack ingestion is a distinct scope requiring an accepted channel/source contract; the existing notification connection can be described as notification delivery only. Emma needs a stored observation that makes no provider request; its execution, transcript, analysis and recovery state are distinct from carrier records. Number inventory must be fresh before it can support a carrier badge.
4. Reuse existing authenticated reader and request-session guard when mounted: key by signed-in actor and tenant, clear before read/context switch, reject late/out-of-order responses, clear on logout/denial, expire evidence and recheck authority. No private-table or provider fallback after denial. This preview has no reader/cache transport to weaken.
5. Separate `test.openfolk.ai` provisioning, supported deployment manifest, exact publication authority, synthetic-only preview backend and independent acceptance remain prerequisites. No frontend or Supabase deployment is included here.

Accounting/research stay deferred and do not block this narrow adapter. No backend migration, auth/RLS policy, connector, credential or provider configuration changed.
